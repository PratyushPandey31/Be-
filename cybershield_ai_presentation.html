Project Objectives & Problem Landscape

Addressing current systemic gaps in enterprise vulnerability management

The Problem Landscape
  • CVE Volume Surge: 25,000+ new CVE disclosures per year overwhelms SOC teams.
  • CVSS Base Inflation: >20% of vulnerabilities rated "Critical" (9.0+), creating worst-case noise.
  • High MTTR Friction: Industry average Mean Time to Remediate stands at 94.0 hours.
  • Severe Alert Fatigue: Measured Alert Fatigue Index of 78.4 / 100 among SecOps analysts.

  • Eliminate Static Triage: Replace single-factor CVSS base scores with dynamic context.

  • Explainable AI (SHAP): Provide human-interpretable feature attribution for auditing.
  • Autonomous Remediation: Synthesize 1-click verified containment scripts (Ansible/Bash).

Data Model 05 / 19

Entity Relationship & Data Model

Relational Schema Mappings & Telemetry Persistence Ledger

Schema Overview
  • Central Hub (assets): Stores IP, hostname, asset type, criticality weight ($W_{crit}$), exposure weight ($W_{exp}$), owner, location.
  • Threat Library (vulnerabilities): Maps CVE ID, title, CVSS base, CWE ID, EPSS score, exploit status, containment script.
  • Relational Mapping (1:N): Links assets to vulnerabilities with detection timestamps and remediation state.
  • Audit Ledger (telemetry_logs): SHA256 scan report hashes, raw output streams, execution times.
[assets] (1) ------------------< (N) [asset_vulnerabilities] >------------------ (1) [vulnerabilities]
TABLE: assets
PK id : INTEGER
name : VARCHAR(100)
ip_address : VARCHAR(45)
asset_type : ENUM
criticality_weight : FLOAT
exposure_weight : FLOAT
owner : VARCHAR(80)
TABLE: vulnerabilities
PK id : INTEGER
cve_id : VARCHAR(20) [UNIQUE]
cvss_score : FLOAT
epss_score : FLOAT
exploit_available : BOOLEAN
patch_script : TEXT
TABLE: asset_vulnerabilities (Junction)
PK id : INT | FK asset_id -> assets(id) | FK vulnerability_id -> vulnerabilities(id)
status : ENUM ('OPEN', 'CONTAINED', 'RESOLVED') | detected_at : TIMESTAMP

Live threat feeds ingestion and wild weaponization boosting

  • Live FIRST.org API Ingestion: Queries live Exploit Prediction Scoring System (EPSS v3) probability scores ($EPSS \in [0.0, 1.0]$).
  • 30-Day Weaponization Likelihood: Measures true mathematical probability of real-world exploitation in the wild over the next 30 days.
  • Non-Linear Threat Amplifier: Formulated as $(1 + \alpha \times \text{EPSS})$, where $\alpha = 0.80$ scaling coefficient.
  • Translates static theoretical CVE severity into active threat probability.
Module 4: Weaponized Exploit Booster
  • Public PoC & Exploit Kit Verification: Cross-references Metasploit modules, GitHub PoC repositories, and CISA KEV catalog.

    1.00× Baseline No Public Exploit Available
  • Immediate Escalation: Forces high priority for low-CVSS vulnerabilities that possess active zero-day exploit kits.

Mathematical Model 08 / 19

Theoretical Formulation: Multi-Factor Mathematical Model

Comprehensive risk formulation and score normalization logic

Primary CyberShield AI Risk Formulation
$$\text{Raw Risk Score} = \text{CVSS}_{\text{Base}} \times W_{\text{criticality}} \times \left(1 + \alpha \cdot \text{EPSS}\right) \times W_{\text{exposure}} \times M_{\text{exploit}}$$
$$\text{Final CyberShield Risk Index} = \min\left(100.0, \frac{\text{Raw Risk Score}}{45.0} \times 100.0\right)$$
Parameter Definitions & Weights
  • $\text{CVSS}_{\text{Base}}$ : NVD Base Score Vector $[0.0 - 10.0]$
  • $W_{\text{criticality}}$ : Asset Business Multiplier $[0.75 - 1.50]$
  • $\text{EPSS}$ : FIRST.org Threat Probability $[0.0 - 1.0]$ ($\alpha = 0.80$)
  • $W_{\text{exposure}}$ : Network Reachability $[0.60 - 1.40]$
  • $M_{\text{exploit}}$ : Weaponization Surge $[1.00 \text{ or } 1.30]$
  • $\text{Floor Normalizer}$ : Fixed Cap Factor ($45.0$)
Risk Score Categorization & SLA
Risk Index Severity Target Remediation SLA
90.0 - 100.0 CRITICAL-URGENT < 4 Hours (P0)
70.0 - 89.9 HIGH < 24 Hours (P1)
40.0 - 69.9 MEDIUM < 7 Days (P2)
0.0 - 39.9 LOW < 30 Days (P3)

Explainable AI 09 / 19

Core Modules: Explainable AI (SHAP) & Risk Attribution

Transparent feature contribution vectors for auditing and SOC compliance

Additive Feature Attribution
$$\text{Risk Score} = \phi_0 + \phi_1(\text{CVSS}) + \phi_2(\text{EPSS}) + \phi_3(W_{crit}) + \phi_4(W_{exp}) + \phi_5(M_{exploit})$$

SHAP (Shapley Additive exPlanations) decomposes the final risk score into exact marginal contributions from each factor, ensuring full model auditability.

  • Court-Admissible Audits: Explains exact score derivation for compliance.
  • SOC Analyst Trust: Eliminates "black-box" AI skepticism.
Marginal Lift Breakdown (Typical Contribution)
CVSS Base Severity ($\phi_1$) +35.0% to +45.0%
EPSS Threat Probability ($\phi_2$) +20.0% to +30.0%
Asset Business Criticality ($\phi_3$) +15.0% to +25.0%
Network Exposure Zone ($\phi_4$) +10.0% to +15.0%
